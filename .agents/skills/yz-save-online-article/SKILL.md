# 保存在线文章到本地笔记库

把在线文章完整保存到本地 vault（本仓库 `/Users/liyazhou/vaults/ai-notes`），保持可读、可离线查看、图片本地化。

## 何时使用

- 用户提供一个 URL（微信公众号 `mp.weixin.qq.com` 或任意网页），要求保存/收藏/备份/存档/抄录到本地。
- 用户说"把这篇存到 xx 目录""收藏这篇文章"等，即使没明说"保存"。

## 核心流程

**优先使用本 skill 自带的脚本** `scripts/save_article.py`，它封装了抓取、解析、下载图片、转 Markdown 的完整流程：

```bash
python3 <skill目录>/scripts/save_article.py <文章URL> <目标目录> [--name 自定义文章名]
```

- 目标目录：**每次调用时由用户指定**（如 `02-agent/02-agenteval`）。用户没说时先询问，不要自作主张挑目录。
- `--name`：可选。默认用原标题生成文件夹/文件名；需要精简名称时传入。

### 具体步骤

1. **确认输入**：从用户消息里取出 URL 和目标目录；缺哪个问哪个。
2. **运行脚本**（用上面命令），脚本会自动：
   - 用移动端 UA 抓页面（微信页面需此处理，否则返回环境验证页）；
   - 提取标题、作者/公众号、发布时间（微信取 `var msg_title`/`nickname`/`ct`，通用网页取 og 标签）；
   - 提取正文（微信取 `#js_content`，通用网页用 readability）；
   - 下载全部图片到 `<YYMM-文章名>/images/`；
   - 转 Markdown 并写入 `<YYMM-文章名>.md`。
3. **检查脚本输出**：
   - 脚本会打印元信息、图片统计、保存路径和问题提示，逐条确认。
   - 若有"下载失败"或"已下载但未出现在 md"的提示，按下方【边界情况】处理。
4. **快速校验**：确认 md 开头有元信息块、正文完整、图片引用与 `images/` 文件对应。
5. **不自动提交 git**：保存完成后不要主动 `git commit`，由用户决定是否提交。

## 命名与结构

- 文件夹与 md 文件同名：`YYMM-文章名称`（YYMM 来自**发布时间**的年月，如 2026-08 发布 → `2608-`）。
- 结构固定为：

```
目标目录/
└── YYMM-文章名称/
    ├── YYMM-文章名称.md
    └── images/          # 全部图片，命名 img-00, img-01, ...
```

- 正文内图片引用一律改为本地相对路径 `images/img-NN.ext`，不用外链。

## md 头部元信息块（固定格式）

```markdown
# 文章标题

> **原文标题**：……
>
> **原文链接**：……
>
> **原文作者**：……（公众号：名字，或作者名）
>
> **发布时间**：YYYY-MM-DD HH:MM
>
> **原文简介**：……（og:description，无则省略）

---
```

## 边界情况

- **微信返回环境验证页**：脚本会检测"环境异常"并报错，稍后重试或换链接，不要强行抓取。
- **图片下载失败**（返回 400 等）：脚本在 md 中保留原链接并在摘要提示。微信图片必须带完整 `?wx_fmt=...&from=appmsg` 参数和 Referer 才能下载，脚本已处理；若仍有失败，向用户说明并保留原链接。
- **表格内联图片被丢弃**：markdownify 转换表格时可能丢掉表格单元格内的图片，脚本会报告"已下载但未出现在 md"。此时需人工在 md 对应位置补回 `![](images/img-NN.ext)`（参照原文章上下文）。
- **解析不出发布时间**：脚本会退回用当天日期生成 YYMM，并在输出中提示"发布时间未知"，转告用户。
- **正文为空**：脚本报"未提取到有效正文"，此时需要人工处理（可能页面结构特殊），不要硬写。

## 脚本说明

- 脚本依赖 `requests`、`beautifulsoup4`、`markdownify`、`readability-lxml`，本机已安装。
- 若脚本异常退出，把报错原样转告用户，不要擅自改脚本逻辑。
