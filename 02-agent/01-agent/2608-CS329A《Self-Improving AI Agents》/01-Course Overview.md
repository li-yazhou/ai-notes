# 01｜Course Overview

> Stanford CS329A《Self-Improving AI Agents》第 1 讲。  
> 课程：Autumn 2025；授课教师：Aakanksha Chowdhery、Azalia Mirhoseini。  
> 内容根据[课程视频](https://www.youtube.com/watch?v=6YnLB0XbTnI&list=PLangBM27OtEA&index=1)与[课程官网](https://cs329a.stanford.edu/)整理，不是逐字稿。

## 一句话总结

这门课研究的不是“怎样让模型一次回答得更好”，而是怎样构造一个闭环系统，使 AI Agent 能从自身输出、验证器、工具执行结果、环境反馈和经验记忆中持续获得信号，并在推理时、训练时乃至系统结构层面改进自己。

## 一、什么是 Self-Improving AI Agent

普通 LLM 应用通常是一条静态链路：

> 输入任务 → 模型生成 → 输出答案

Self-Improving Agent 则形成反馈闭环：

> 任务 → 规划与行动 → 环境反馈 → 评价/验证 → 更新策略、记忆或工具 → 再次行动

可以把 Agent 抽象为：

\[
\text{Agent}=\text{Model}+\text{Tools}+\text{Memory}+\text{Planning}+\text{Feedback}
\]

“自我改进”并不一定意味着在线更新模型参数。只要系统能够利用经验改善后续行为，就可能发生在不同层级：

|层级|被改进的对象|典型手段|
|---|---|---|
|单次推理|当前答案或推理轨迹|多次采样、反思、搜索、验证、重排|
|跨任务经验|记忆与上下文|经验总结、失败案例、检索、长期记忆|
|能力边界|工具与工作流|工具调用、代码执行、新工具生成、流程编排|
|模型行为|策略或参数|SFT、奖励模型、强化学习、合成数据训练|
|Agent 系统|架构与组件组合|自动搜索 prompt、角色、拓扑、验证器和推理结构|

## 二、为什么需要自我改进

### 1. 预训练模型是静态的，真实世界是动态的

模型训练结束后，参数中的知识和策略基本固定；但部署环境、工具接口、任务要求和用户偏好会不断变化。Agent 必须通过检索、记忆和反馈适应这些变化。

### 2. 长程任务不能靠一次生成完成

编码、科研、网页操作和机器人任务通常包含多步决策。早期的一个小错误会沿轨迹放大，因此系统需要在执行过程中检查状态、发现偏差、重新规划并恢复。

### 3. 模型“能生成正确答案”不等于“能稳定得到正确答案”

同一模型对同一任务的不同采样可能得到不同结果。扩展推理计算可以提高正确轨迹的覆盖率，但必须有足够可靠的验证器把好答案选出来。

### 4. 环境交互提供了预训练数据之外的新监督

代码能否编译、测试是否通过、网页操作是否成功、机器人是否完成目标，都可转化为反馈。Agent 的关键机会在于把这些反馈变成下一轮决策或训练所需的信号。

## 三、自我改进闭环

一个通用闭环包含六个步骤：

1. **提出任务或生成课程（Task/Curriculum）**：来自用户、数据集，也可以由系统根据当前能力自动构造。
2. **探索与行动（Act）**：模型规划、调用工具，并生成一条或多条候选轨迹。
3. **收集反馈（Observe）**：读取工具返回值、测试结果、环境状态或人类反馈。
4. **评价与验证（Evaluate/Verify）**：判断结果是否正确、过程是否可靠，以及失败发生在哪里。
5. **提炼经验（Reflect/Learn）**：把成功策略和失败原因转化为记忆、规则、训练样本或奖励。
6. **更新并重试（Update）**：修改上下文、搜索策略、工具、Agent 架构或模型参数，再进入下一轮。

其中最难的往往不是生成更多候选，而是获得**可靠、可扩展、难以被投机利用的反馈**。

## 四、课程的核心技术主线

### 1. 测试时计算扩展（Test-Time Compute Scaling）

在不改变参数的情况下，为难题分配更多推理计算：

- 重复采样多个答案；
- 使用 best-of-N、投票或奖励模型选择；
- 通过反思与迭代修正答案；
- 用 tree search / beam search 探索不同推理路径；
- 根据题目难度动态分配计算预算。

关键问题是：候选数量增加后，验证器能否可靠识别正确结果？详见 [[02-Test-Time Compute Scaling]]。

### 2. 鲁棒验证（Robust Verification）

验证器为改进闭环提供目标信号，常见类型包括：

- **规则或执行验证器**：单元测试、编译器、形式化规则、仿真器；
- **Outcome Verifier**：只评价最终结果；
- **Process Verifier**：评价中间推理步骤；
- **Reward Model / LLM Judge**：学习或生成式评价；
- **人类反馈**：质量高但成本和吞吐量受限。

系统必须警惕 reward hacking：Agent 可能学会迎合评估指标，而不是真正完成任务。

### 3. 从工具和代码反馈中学习

工具把语言模型接入外部世界，同时提供可观察反馈：

- 搜索与检索补充新知识；
- 代码执行把想法转化为可验证实验；
- API 和网页交互使 Agent 能实际完成任务；
- 测试、异常和返回状态成为低成本监督信号。

这条主线把“推理”扩展为 ReAct 式的循环：

> Reason → Act → Observe → Update

### 4. 多步推理、规划与搜索

长程任务要求 Agent：

- 分解目标与维护中间状态；
- 在广度探索与深度修正之间分配预算；
- 识别失败并回退；
- 并行执行相互独立的子任务；
- 在新信息到来后重新规划。

搜索不仅用于找答案，也用于寻找更好的计划、工具调用序列和 Agent 结构。

### 5. 训练时扩展与强化学习

测试时产生的高质量轨迹可以回流训练：

1. 生成多条解题/行动轨迹；
2. 用环境或验证器筛选；
3. 将成功轨迹转化为监督数据或奖励；
4. 更新策略模型；
5. 更强的模型再生成更难数据。

这构成“生成数据—验证—训练—再生成”的自举循环。其上限受验证质量、探索多样性和训练稳定性制约。

### 6. 开放式演化与自动化 Agent 设计

更高层次的自我改进不只优化回答，而是让系统设计自身：

- 自动生成或选择 prompt；
- 发明、修改和复用工具；
- 搜索多 Agent 的角色分工与通信拓扑；
- 产生逐渐更难的课程；
- 自动提出假设、运行实验并修改方案。

当“能力生成器”与“难度生成器”相互推动时，系统才可能持续突破固定数据集的上限。

### 7. 记忆、多模态交互与真实应用

课程还将自我改进放进完整 Agent 系统中研究：

- **记忆**：压缩、存储和检索跨任务经验；
- **多模态交互**：理解屏幕、图像和物理环境；
- **编码 Agent**：利用测试和执行反馈迭代软件；
- **深度研究 Agent**：搜索、综合、引用并验证开放式结论；
- **机器人 Agent**：在真实或模拟环境中感知、规划与控制。

## 五、统一理解：三个扩展轴

可以把整门课理解为同时扩展三个轴：

|扩展轴|核心问题|代表方法|
|---|---|---|
|推理时扩展|一次任务上多花计算是否更好？|采样、搜索、反思、验证|
|训练时扩展|如何把交互经验固化到模型？|合成数据、SFT、RL、自举|
|系统级扩展|如何扩展模型之外的能力？|工具、记忆、多 Agent、架构搜索|

三者之间形成飞轮：

> 更强的推理与工具使用 → 产生更高质量轨迹 → 更可靠的验证与筛选 → 训练出更强模型 → 处理更难任务

## 六、课程所强调的关键瓶颈

### 1. 生成—验证鸿沟

系统也许已经生成了正确候选，却没有能力把它选出来。数学、代码等可自动验证领域更容易建立自我改进闭环；开放式写作、研究综合和主观任务则更困难。

### 2. 误差累积与长程可靠性

单步准确率很高并不保证长轨迹成功。任务越长，状态漂移、工具失败、遗漏约束和错误恢复就越重要。

### 3. 分布外泛化

Agent 可能只学会某个 benchmark 或验证器的捷径。真正的改进必须迁移到新任务、新工具和新环境。

### 4. 成本与预算分配

更多采样、搜索和验证意味着更高延迟与 Token 成本。好的 Agent 要识别问题难度，把额外计算用在最可能获得边际收益的位置。

### 5. 安全与可控性

越能自主修改记忆、工具、策略和目标的系统，越需要：

- 权限边界与沙箱；
- 可审计的行动轨迹；
- 防止目标漂移和奖励投机；
- 在高风险操作前引入人类监督。

## 七、评估 Self-Improving Agent 的方式

不能只比较改进后的最终分数，还要衡量“改进过程”本身：

|维度|需要回答的问题|
|---|---|
|能力提升|经过若干轮交互后，成功率提高了多少？|
|样本效率|需要多少任务、反馈和训练样本？|
|计算效率|额外 Token、调用次数、延迟和成本是多少？|
|泛化能力|改进能否迁移到未见任务与环境？|
|持续性|新能力会不会导致旧能力遗忘？|
|鲁棒性|面对噪声反馈、工具故障和分布变化是否稳定？|
|安全性|是否出现 reward hacking、越权或不可逆错误？|

尤其应避免只在同一评测集上反复优化；否则测到的可能是 benchmark overfitting，而非通用的自我改进能力。

## 八、课程组织与学习方式

这是一门研究型研究生研讨课，学习重点不是记住固定结论，而是：

- 阅读并讨论最新论文；
- 通过三次作业建立对自我改进、多步推理和工具使用的直觉；
- 2—4 人组队完成原创研究项目；
- 从学术界和工业界嘉宾处理解编码、科研助手和机器人等真实应用。

课程由 20 次课构成，可按四个阶段理解：

1. **自我改进基础**：测试时扩展、验证、工具反馈、规划、训练时 RL；
2. **开放式系统**：Agent 演化、搜索与 Deep Research；
3. **系统与应用**：软件工程 Agent、记忆、推理、长程评估、机器人；
4. **研究实践**：中期汇报、最终项目与未来研究方向。

## 九、对后续学习最重要的五个问题

1. **反馈从哪里来？** 是规则、执行环境、模型评审还是人类？
2. **反馈是否可信？** 会不会有偏差、噪声或被 Agent 利用？
3. **系统究竟更新什么？** 当前答案、记忆、工具、工作流还是模型参数？
4. **改进是否泛化？** 是学会了通用策略，还是只拟合了评测器？
5. **收益是否值得成本和风险？** 能力增量是否覆盖额外计算、延迟和安全代价？

## 十、核心结论

- **自我改进是一种闭环系统属性，不是某一个单独算法。**
- **反馈质量决定改进上限；验证器往往比生成器更稀缺。**
- **推理时搜索能暴露模型已有能力，训练则把成功经验固化为新的能力。**
- **工具、代码和环境让 Agent 获得可执行、可验证的学习信号。**
- **真正困难的是在长程、开放式和分布外任务中实现稳定且安全的持续改进。**
